# shkaf-hud

Домашний дашборд для Unraid-сервера: Arduino Pro Micro с WS2812-лентой (4 бара
градиентной подсветки) и OLED-экраном показывает загрузку CPU/RAM/сети/дисков/
массива/BigCache в реальном времени, а также статистику Plex и что сейчас
смотрят (через Tautulli) — с полностью настраиваемым конструктором экранов
через веб-интерфейс, без единой перепрошивки платы.

Управляется контейнером `shkaf-hud`, который собирает статистику хоста, шлёт
её по USB-serial на плату, и отдаёт веб-интерфейс (в т.ч. устанавливаемый как
PWA) для настройки лент, цветов и OLED-экранов.

## Что показывает

**Лента (WS2812)** — 4 бара по 8 диодов, каждый — 3-стопный градиент
(0% → 50% → 100%), полностью настраиваемый в веб-интерфейсе:
- Цвета каждого из 3 стопов — отдельным пикером на бар
- Чекбокс "цвет на 100%" — при достижении 100% бар заливается финальным
  цветом сплошняком вместо градиента; выключен по умолчанию (градиент всегда)
- На каждый бар назначается любая метрика: CPU / RAM / NET / DISK %util /
  Array % / BigCache % / температура CPU
- Общая яркость ленты — один слайдер

**OLED (128×64 SSD1306, I2C)** — конструктор экранов через `/screens`:
- Контраст экрана регулируется слайдером на главной странице (0-255,
  по умолчанию 255 - максимум), сохраняется между перезапусками контейнера
- Каждый экран — 3 строки текста, собираются из литерального текста +
  `{переменных}` (`Cache {cache_pct}%`, `↓ {net1_rx}` и т.п.) — полный список
  переменных с легендой прямо на странице редактора
- Экраны создаются/удаляются/сортируются (drag-n-drop) через веб-интерфейс,
  время показа настраивается для каждого экрана отдельно
- "Повторяющиеся" экраны (активные стримы Plex, недавно добавленное) сами
  разворачиваются в N копий по числу реальных элементов и пропадают из
  ротации, если элементов ноль
- Если в шаблоне экрана используется переменная, которая сейчас не резолвится
  (например второй сетевой интерфейс не выбран) — экран целиком пропускается
- Строки длиннее экрана скроллятся сами (Arduino меряет реальную ширину через
  `getTextBounds`), короткие — печатаются статично

Дефолтный набор из 7 экранов уже настроен из коробки: Storage, CPU/RAM,
Network 1, Network 2, Plex, Streams (по потоку на каждый активный), RecentAdd
(по недавнему добавлению) — редактируется/расширяется на `/screens`.

OLED работает на U8g2 в постраничном режиме (кириллический шрифт,
`u8g2_font_*_cyrillic`) — названия фильмов/сериалов на русском отображаются
корректно. Размер шрифта переключается константой `OLED_FONT_SIZE` (1-4) в
начале `.ino`.

## Железо

- Arduino Pro Micro (32u4 / Leonardo-совместимая)
- WS2812 LED-матрицы (в оригинальной сборке - 2 шт 4x4, физически расположены как 4
  вертикальных бара по 8 диодов)
- OLED SSD1306 128x64, I2C
- Библиотеки для прошивки: FastLED, U8g2

## Установка на Unraid (через GUI, образ из ghcr.io)

1. **Docker** → **Add Container**
2. В поле **Template** вставить:
   ```
   https://raw.githubusercontent.com/RGCustom/shkaf-hud/main/shkaf-hud.xml
   ```
3. Форма подтянется автоматически - заполнить свои значения (Tautulli URL/ключ, путь к
   Pro Micro, сетевые интерфейсы и т.д.) → **Apply**

Подробности по каждому полю - см. таблицу переменных ниже.

### Обновление контейнера

```bash
docker pull ghcr.io/rgcustom/shkaf-hud:latest
docker stop shkaf-hud && docker rm shkaf-hud
```
и заново **Add Container** → **Template** → `shkaf-hud` (подхватит сохранённый персональный
конфиг). Либо включить автообновление через плагин **Community Applications** → **Auto Update
Applications**.

Версия реально запущенного кода видна в первой строке `docker logs shkaf-hud`.

## Установка через docker-compose (вне Unraid)

```bash
cp .env.example .env
# заполнить .env своими значениями
docker compose up -d --build
```

## Переменные конфигурации (env)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `SERIAL_PORT` | `/dev/ttyACM0` | Путь к USB-устройству Pro Micro внутри контейнера |
| `BAUD` | `115200` | Скорость serial, должна совпадать со скетчем |
| `TAUTULLI_URL` | `http://127.0.0.1:8181` | Адрес Tautulli |
| `TAUTULLI_API_KEY` | - | Settings → Web Interface → API в Tautulli |
| `QBT_URL` | `http://127.0.0.1:8080` | Адрес WebUI qBittorrent |
| `QBT_API_KEY` | - | Пусто = интеграция выключена. Settings → WebUI → API Key → Generate (qBittorrent ≥ 5.2.0 / WebAPI ≥ 2.14.1) |
| `NET_IFACE` | `br0` | Интерфейс для LED-бара с метрикой "NET" (общая нагрузка) |
| `NET_MAX_MBPS` | `500` | Что считать 100% на LED-баре "NET" |
| `DISK_DEVICES` | пусто (автоопределение) | Список дисков через запятую для %util, напр. `sdb,sdc` |
| `ARRAY_PATH` | `/mnt/user` | Точка монтирования массива |
| `ARRAY_REFRESH_SECONDS` | `60` | Как часто пересчитывать место на массиве |
| `CACHE_PATH` | `/mnt/cache` | Точка монтирования пула BigCache |
| `CACHE_REFRESH_SECONDS` | `60` | Как часто пересчитывать загрузку BigCache |
| `CPU_TEMP_MAX_C` | `90` | Что считать 100% для LED-бара "температура CPU" |
| `LIBRARY_REFRESH_SECONDS` | `300` | Как часто обновлять счётчики Movies/Series/Songs |
| `RECENT_REFRESH_SECONDS` | `120` | Как часто опрашивать Tautulli на новые добавления |
| `RECENT_MAX_AGE_DAYS` | `5` | Не показывать добавленное старше N дней |
| `RECENT_COUNT` | `5` | Сколько последних добавлений запрашивать |
| `POLL_INTERVAL` | `1.0` | Как часто пересчитывать метрики и проверять изменения |
| `FULL_RESYNC_SECONDS` | `30` | Как часто слать Arduino полное состояние целиком (страховка на случай перезагрузки платы) |
| `WEB_PORT` | `8189` | Порт веб-интерфейса |
| `CONFIG_DIR` | `/config` | Куда сохраняются настройки (цвета, экраны, выбранные интерфейсы) |

Сеть контейнера - `host` (нужно для честного чтения `/proc/net/dev` хоста и доступа к
сервисам вроде Tautulli независимо от того, в какой docker-сети они сами находятся).

Сетевые интерфейсы для экранов Network 1/2, сами экраны и их порядок/время показа -
настраиваются в веб-интерфейсе (`/` и `/screens`), не через env.

## Протокол Pro Micro <-> хост

Строка по serial раз в `POLL_INTERVAL`, **только изменившиеся с прошлого тика поля**
(если ничего не поменялось - не шлётся вообще ничего; раз в `FULL_RESYNC_SECONDS`
всё равно шлётся полное состояние целиком, на случай если плата перезагрузилась/
потеряла кусок данных):

```
BAR1:<48 hex-символов>   - 8 пикселей бара x RRGGBB, склеенные подряд без разделителей.
BAR2, BAR3, BAR4           Цвет каждого светодиода уже посчитан на сервере (ledbar.py):
                            градиент/solid-режим/% заполнения - вся эта логика ушла с
                            платы в Python, Arduino просто раскладывает готовые цвета
                            по своим физическим диодам через LED_MAP.
BRI:<0-100>               - яркость ленты
CON:<0-255>               - контраст OLED (по умолчанию 255)
L1:<текст>, L2:<текст>, L3:<текст> - три строки OLED, уже полностью готовые к печати (UTF-8)
```

Всего 9 переменных. Arduino ничего не считает и не форматирует - только раскладывает
пришедшее по 4 барам (8 диодов на бар) и 3 строкам экрана; вся логика (градиенты,
метрики, шаблоны, ротация, решение "скрыть экран, если данных нет") - на сервере.

## Конструктор OLED-экранов

Открой `/screens` в браузере (или установи как PWA - иконка появится на
рабочем столе/домашнем экране телефона). Для каждого экрана:

- **Название** - только для интерфейса, на дисплей не попадает
- **Строки 1-3** - текст с `{переменными}`, легенда прямо на странице (клик по
  переменной вставляет её в поле, на котором сейчас фокус)
- **Время показа** - в секундах, у каждого экрана своё
- Живое превью того, что реально отрендерится, прямо по мере набора текста

Формат переменной: `{имя}` или `{имя:N}` (обрезать/дополнить строку до N символов,
удобно для имён пользователей) или `{имя:.2f}` (формат числа, как в Python).

Экраны с переменными из повторяющихся групп (`stream_*`, `recent_*`, `qbt_*`)
автоматически разворачиваются в несколько копий - по одной на каждый активный
стрим/недавнее добавление/торрент - и пропадают из ротации при нуле элементов.

## Прошивка Arduino прямо из контейнера

Прошивать плату можно удалённо, без физического доступа к серверу и без
Arduino IDE - через `/flash` в веб-интерфейсе.

**Как это работает:**

1. Компилируешь `.ino` в `.hex` любым удобным способом (Arduino IDE:
   Sketch → Export compiled Binary - файл появится рядом со скетчем).
2. Открываешь `/flash`, перетаскиваешь `.hex`, жмёшь **Прошить**.
3. Контейнер сам:
   - шлёт плате сигнал перезагрузки в бутлоадер (штатный 1200-бод touch,
     как делает Arduino IDE);
   - находит появившийся bootloader-порт (Leonardo поднимает его под
     новым именем `/dev/ttyACMx` - номер заранее не предсказуем);
   - заливает прошивку через `avrdude`, лог видно построчно прямо в браузере.
4. Обычный обмен данными (лента/OLED) на это время приостанавливается и
   возобновляется автоматически сам, как только плата перезагрузится обратно
   в скетч - ничего руками перезапускать не нужно.

**Требование:** контейнеру нужен доступ к `/dev` хоста, чтобы увидеть
временный bootloader-порт (одного примонтированного `by-id`-пути платы для
этого недостаточно - у бутлоадера своего стабильного `by-id` ещё нет). В
шаблоне `shkaf-hud.xml` это уже настроено через `Extra Parameters`:

```
-v /dev:/dev --device-cgroup-rule='c 166:* rmw'
```

`166` - major-номер класса `ttyACM` в ядре Linux; правило открывает доступ
только к USB-serial устройствам этого класса, не ко всему `/dev` хоста.
Если контейнер создан вручную, а не из XML-шаблона - добавь этот же параметр
в Extra Parameters контейнера в Unraid и пересоздай его.

Не отключай плату и не перезапускай контейнер, пока идёт заливка - процесс
занимает несколько секунд и разово.

## Калибровка ленты

Порядок физического подключения матриц в цепочку неизвестен заранее - в скетче есть
режим калибровки: пришли `CAL` в Serial Monitor, диоды по одному загорятся белым с
номером в консоли, дальше нужно вручную заполнить массив `LED_MAP` в `.ino` под свою
раскладку.
